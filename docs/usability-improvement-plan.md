# DesktopSessionManager 사용성 개선 계획

작성일: 2026-10-14  
상태: 1~7단계 구현 완료 (v0.5.0). 자동 검증 통과, 실제 Windows 환경 확인은 7절 체크리스트 기준으로 진행 필요

## 1. 목표

작업환경 저장·수정·복원에 필요한 조작을 줄이고, 복원 실패를 쉽게 확인하고 해결할 수 있도록 한다. 기존 WinForms 구조와 프로필 JSON 호환성을 유지하면서 단계적으로 개선한다.

핵심 사용 흐름은 **프로필 수정 → 현재 배치로 갱신 → 빠르게 복원 → 실패 항목 해결**이다.

## 2. 현재 기능과 개선 방향

기존 프로젝트는 창 검색, 드래그를 통한 프로필 구성, 프로젝트 감지, 앱별 복원, 가상 데스크톱 이동과 창 위치 복원을 제공한다.

이번 계획에서는 반복 작업을 줄이는 기능을 먼저 구현한다. 프로필 편집과 현재 상태 갱신을 개선한 뒤 트레이에서 빠르게 실행하도록 하고, 이후 복원 제어와 복구 기능을 확장한다.

## 3. 배포 단위와 구현 순서

| 배포 단위 | 단계 | 주요 결과 |
| --- | --- | --- |
| 1차: 일상 작업 간소화 | 1~3 | 앱을 다시 열거나 창을 다시 추가하지 않고 프로필을 수정·갱신하고 빠르게 복원 |
| 2차: 복원 제어와 문제 해결 | 4~5 | 필요한 항목만 복원하고 진행 상황을 확인하며 실패 항목만 재시도 |
| 3차: 복구와 환경 변화 대응 | 6~7 | 이전 프로필 복구, 모니터 구성 변화 대응, 연동 상태 확인 |

일정은 확정하지 않는다. 각 단계의 완료 기준과 검증을 충족한 뒤 다음 단계로 진행한다.

## 4. 단계별 구현 계획

### 1단계. 프로필 직접 수정

저장된 창을 선택하면 편집 창에서 프로젝트·파일 경로, 대상 데스크톱, 최대화·최소화 상태를 수정할 수 있도록 한다.

- 대상 앱이 실행 중이지 않아도 편집할 수 있다.
- 앱별 플러그인 규칙에 맞는 경로 선택과 유효성 검사를 제공한다.
- 변경 사항을 저장하기 전까지 기존 프로필 파일을 유지한다.

**완료 기준:** 닫힌 앱의 프로필 항목을 수정·저장·다시 불러올 수 있고, 잘못된 경로와 수정하지 않은 항목을 구분할 수 있다.

### 2단계. 현재 상태로 갱신

프로필에 등록된 창을 실행 중인 창과 연결해 위치·크기·최대화·최소화 상태 및 대상 데스크톱을 갱신한다. 적용 전에 변경 내역을 보여준다.

- 같은 앱의 여러 창은 프로젝트 경로 등 식별 정보를 활용해 연결한다.
- 연결이 모호하면 사용자가 대상 창을 선택하도록 한다.
- 닫힌 창은 기본적으로 유지하고, 제거는 명시적으로 선택한다.
- 새로 열린 창은 자동으로 추가하지 않고 사용자가 선택해서 추가한다.

**완료 기준:** 창을 다시 드래그하지 않고 기존 프로필을 갱신할 수 있으며, 다른 프로젝트의 창이 임의로 연결되거나 닫힌 창이 사라지지 않는다.

### 3단계. 트레이 빠른 실행

트레이에서 즐겨찾기·최근 프로필을 선택해 복원할 수 있도록 한다. 전역 단축키와 트레이 동작 설정을 제공한다.

- 메인 창 열기, 프로필 복원, 명시적인 종료 메뉴를 제공한다.
- 창 닫기 시 종료할지 트레이로 보낼지 설정할 수 있다.
- 전역 단축키 등록 실패나 충돌을 안내한다.
- 복원 중 중복 실행을 방지한다.

**완료 기준:** 메인 창을 열지 않고 프로필을 복원할 수 있고, 단축키 충돌과 종료 동작이 사용자에게 명확하다.

### 4단계. 선택 복원과 배치만 복원

복원 전 항목별 예상 동작을 표시하고 필요한 창만 선택하도록 한다.

- 기존 창 재사용, 새 앱 실행, 경로 확인 필요 항목을 구분한다.
- 부족한 가상 데스크톱과 사용할 수 없는 경로를 미리 안내한다.
- 배치만 복원 모드에서는 실행 중인 창의 위치와 데스크톱만 정리한다.
- 미리보기 후 실행 상태가 바뀔 수 있으므로 실행 직전에 대상을 다시 확인한다.

**완료 기준:** 선택한 항목만 복원하며, 배치만 복원 모드에서는 새 앱을 실행하지 않는다.

### 5단계. 복원 진행과 실패 처리

항목별 진행 상태와 결과를 보여주고, 남은 작업 중단 및 실패 항목 재시도를 지원한다.

- 전체 진행 개수와 현재 대기 중인 앱을 표시한다.
- 실행 파일 없음, 프로젝트 경로 오류, 창 탐색 시간 초과, 이동 실패 등을 구분한다.
- 실패 항목의 경로를 수정하고 해당 항목만 재시도할 수 있도록 한다.
- 중단은 이후 작업을 멈춘다. 이미 실행하거나 이동한 창을 자동으로 되돌리지는 않는다.

**완료 기준:** 전체 복원을 반복하지 않고 실패한 항목만 해결할 수 있으며, 중단 후 추가 실행·이동이 계속되지 않는다.

### 6단계. 백업과 복구 이력

프로필 덮어쓰기 전에 이전 버전을 보관하고, 이력에서 선택해 복구할 수 있도록 한다.

- 저장 시각과 프로필 이름을 기준으로 이력을 표시한다.
- 보관 개수를 제한하고 오래된 백업을 정리한다.
- 복구 전 현재 프로필도 보관한다.
- 수동 백업·복구를 검증한 뒤 선택형 주기적 자동 저장을 추가한다.
- 자동 저장은 별도 복구용 프로필에 기록해 수동 프로필을 덮어쓰지 않는다.

**완료 기준:** 잘못 덮어쓴 프로필을 복구할 수 있고, 보관 제한과 자동 저장이 수동 프로필에 영향을 주지 않는다.

### 7단계. 모니터별 배치와 연동 안내

같은 프로필에 노트북 단독·다중 모니터 등 구성별 배치를 저장한다. 앱별 복원 연동 상태도 표시한다.

- 모니터 구성과 작업 영역을 기록하고 현재 환경에 맞는 배치를 선택한다.
- 일치하는 구성이 없으면 현재 화면에서 접근 가능한 위치로 보정한다.
- 해상도와 화면 배율 변경을 고려한다.
- Aseprite 확장 연결, 열린 파일 정보 수신, 프로젝트 감지 상태를 표시한다.
- 상태 정보가 없거나 오래된 경우 정상 연결로 단정하지 않는다.

**완료 기준:** 모니터 연결·해제 이후에도 창에 접근할 수 있고, 저장 전에 프로젝트·파일 복원 가능 여부를 확인할 수 있다.

## 5. 구현 원칙

### 프로필 호환성

기존 프로필 형식을 계속 읽고, 추가 필드는 기본값으로 처리한다. 형식 변경이 필요하면 스키마 버전과 변환 경로를 명확히 정의한다.

### 창 연결 로직 공유

현재 상태 갱신과 복원에서 같은 창 판별 기준을 사용하도록 로직을 분리한다. 실행 파일이 같다는 이유만으로 다른 프로젝트의 창을 연결하지 않으며, 불확실한 연결은 사용자에게 표시한다.

### 안전한 저장

임시 파일에 기록한 뒤 교체하는 저장 방식을 적용한다. 실패 시 기존 프로필을 유지하고 원인을 안내한다. 이 저장 기반은 1차 배포부터 적용하며, 사용자에게 노출되는 백업 이력 기능은 6단계에서 추가한다.

### 역할 분리

현재 화면 중심 코드에서 프로필 저장, 창 연결, 복원 실행, 설정 관리를 필요한 만큼 분리한다. 트레이와 메인 화면은 동일한 복원 경로를 사용해 동작 차이를 줄인다.

### 복원 범위 명확화

복원은 앱 실행과 프로젝트·파일 열기, 창 배치를 대상으로 한다. 앱 내부의 저장되지 않은 편집 내용은 복구 대상으로 취급하지 않는다.

## 6. 검증 계획

| 검증 항목 | 확인할 내용 | 방식 |
| --- | --- | --- |
| 기존 프로필 | 이전 형식 읽기, 새 필드 기본값, 저장 후 재읽기 | 자동 검증 |
| 창 연결 | 같은 앱의 여러 프로젝트, 동일·유사 제목, 대상 부재 | 판별 로직 자동 검증 + Windows 확인 |
| 상태 갱신 | 변경 내역, 닫힌 창 유지, 모호한 연결 선택 | Windows 확인 |
| 저장과 복구 | 저장 실패 시 원본 유지, 백업 생성과 복원 | 자동 검증 |
| 트레이와 단축키 | 충돌 안내, 창 닫기 설정, 명시적 종료, 중복 복원 방지 | Windows 확인 |
| 선택 복원 | 선택한 항목만 실행, 배치 모드에서 신규 실행 없음 | 자동 검증 + Windows 확인 |
| 복원 중단·재시도 | 중단 후 추가 작업 없음, 성공 항목 중복 실행 없음 | 자동 검증 + Windows 확인 |
| 가상 데스크톱 | 부족한 데스크톱, 고정 창, 모든 데스크톱 창 처리 | Windows 확인 |
| 모니터 변화 | 연결·해제, 해상도·배율 변경, 화면 밖 창 보정 | Windows 확인 |
| 앱 연동 | Aseprite 정보 없음·오래됨, 사라진 파일, 프로젝트 감지 실패 | 상태 판별 검증 + 실제 앱 확인 |

각 배포 단위마다 빌드와 해당 변경에 필요한 검증을 완료하고, 기존 저장·복원 흐름에 회귀가 없는지 확인한다.

## 7. 첫 배포 완료 체크리스트

- [ ] 대상 앱을 실행하지 않고 프로필 항목을 수정할 수 있다.
- [ ] 현재 배치로 갱신하기 전에 변경 사항을 확인할 수 있다.
- [ ] 닫힌 창과 연결이 모호한 창을 임의로 삭제·갱신하지 않는다.
- [ ] 트레이에서 프로필을 복원할 수 있다.
- [ ] 전역 단축키 충돌을 안내하고 종료 동작을 설정할 수 있다.
- [ ] 기존 프로필을 읽을 수 있고 저장 실패 시 원본이 유지된다.
- [ ] 같은 앱의 여러 프로젝트와 가상 데스크톱 환경에서 검증을 완료한다.

## 8. 계획의 근거

이 문서는 프로젝트의 README와 소스 코드 검토, 대화에서 정리한 개선 우선순위를 기반으로 작성했다. 실제 사용자 화면 관찰이나 구현 완료 보고서는 아니며, 작성 시점에는 모든 단계가 구현 전 계획이었다.
